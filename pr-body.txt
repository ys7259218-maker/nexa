# Compliance opt-out is unconditional + register the never-run optedOutCustomers suite

Query/page/test/docs-only. **No migrations, no production changes.**

## Why

WhatsApp compliance requires honoring opt-out (STOP) keywords immediately — a
business that keeps drafting (let alone sending) after a customer asks to stop
risks platform penalties. Inbound opt-out detection was gated behind the
off-by-default `CONVERSATION_SAFETY_ENABLED` flag, so with the flag off (the
default) a "STOP" message was **not** durably recorded and the message **did**
flow into the AI-draft path. The test suite even locked that in
("disabled conversation safety flag preserves the existing draft flow").

A customer asking to stop must be recorded and never drafted regardless of an
optional automation roll-out flag.

## What changed

- `lib/whatsappIngest.ts`
  - `customerOptedOut` is now computed from message content alone (the
    `conversationSafetyEnabled &&` prefix is gone), so the existing durable
    service-role RPC (`mark_conversation_customer_opt_out`) always runs.
  - `conversationAllowsDraft` is forced `false` on opt-out in both flag states;
    the flag now gates only the rest of the safety surface (human takeover /
    automation mode).
- `lib/whatsappIngest.test.ts` — re-pinned the flag-off behavior:
  "customer opt-out is honored even when the conversation-safety flag is
  disabled" now asserts the RPC runs, the conversation is marked
  `whatsapp_keyword`, and no AI draft is created.
- **Test-suite integrity (this PR):** `lib/optedOutCustomers.test.ts` was written
  but **never registered in the `npm test` file list** — and the registered-equivalent
  breakage would have failed anyway: the `not(...)` mock was `async`, so `.order()`
  was called on a Promise (`...`.not(...).order is not a function`). Registered the
  suite in `package.json` and fixed both mocks.
- `lib/optedOutCustomers.ts` — removed the phantom `OptOutSource` value `"system"`,
  which the conversation-safety check constraint forbids (only `'whatsapp_keyword'`
  is legal whenever opt-out is set); the `"System"` label was unreachable.
- Docs updated (`README.md`, `NEXA_PROJECT_RECAP.md`, `docs/BLUEPRINT.md`,
  `NEXA_HANDOFF.md`) to state that opt-out recording/draft-blocking run
  unconditionally while `CONVERSATION_SAFETY_ENABLED=false` remains the safe
  default for the rest of the safety surface.
