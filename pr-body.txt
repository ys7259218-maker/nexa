## Changes
Every inline feedback element in the app is auto-focused the moment a save result appears (`role="status"` / `alert`, `tabIndex={-1}`). That focus call was `focus()`, which scrolls the focused element into view. Because the feedback sits right under a long form, announcing success/error would yank the page down past all the fields and disorient the user.

All focus calls now use `focus({ preventScroll: true })`, so the message is announced for screen readers (still focused, still `aria-live`) without scrolling the page. This covers the shared `SettingsFeedback` and `AuthFeedback` components plus the inline-ref forms: `GeneralSettings`, `NewAIEmployeeForm`, `EmployeeTestSandbox`.

## Notes
- Code-only, semantics-only change; no layout or logic touched.
- Contract tests now assert the `preventScroll: true` option instead of the bare `focus()`.
