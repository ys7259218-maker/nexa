## Changes
Every streaming `loading.tsx` shell now declares an accessible busy region so assistive tech announces loading state consistently:

- **clearly labelled + busy**: added `aria-busy="true"` to the two settings shells that only had a label (issues, team)
- **neither present**: added `aria-busy="true"` + `aria-label="Loading <route>"` to conversations, dashboard, AI employees, and the AI Employee detail shells
- **plain text**: upgraded the knowledge-sources shell from a bare text line to the standard pulsing skeleton with a busy label

The existing AI Employee subpage shells (knowledge, test, versions) already used `aria-busy="true"` + `aria-label` and are unchanged. All 10 loading shells now follow one convention.

## Notes
- Accessibility-only change; no visual/layout impact beyond the sources shell matching its siblings.
- Contract test now sweeps every loading shell, asserting both `aria-busy="true"` and a matching `Loading ...` label.
