Human-approved outbound sends are now recorded in the immutable audit trail.

## What changes
- New migration `20260905140000_outbound_audit_trail.sql` (+ docs mirror):
  - Widens `audit_events.entity_type` allow-list to include `'message'` (recreating the check with the new value only).
  - Adds a security-definer `audit_outbound_message_sent` `AFTER UPDATE OF status` trigger on `messages`. When a row transitions to status `'sent'`, it writes an audit row (`action='outbound_message_sent'`) carrying only ids, from/to status, `wa_message_id`, `template_name`, `sent_at`, and `conversation_id` — never the message body.
  - Workspace is resolved from the owning conversation so the existing workspace-members read policy scopes the row; audition is actor-null because `sent` is written by the service-role outbound processor.
  - Trigger function is fully `revoke`-guarded; no client write policy added.
- `docs/GO_LIVE.md`: checklist now reads "all migrations applied in order" instead of a stale count.
