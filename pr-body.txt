Operators can now send a Meta template message **even while the 24-hour customer-service window is open**, not only after it closes. This completes the WhatsApp template-send surface from the roadmap.

## What changes
- `lib/server/draftSender.ts`:
  - New `preferTemplate` option on `sendApprovedDraft`. When the caller explicitly chooses a template, a validated template is used regardless of window state (previously the server always preferred the free-form draft while the window was open, so templates were only possible after it closed).
  - Distinct fail-closed message when `preferTemplate` is set but no template name is supplied.
- `app/api/outbound/draft/route.ts`: reads `preferTemplate: true` from the JSON body and forwards it.
- `components/conversations/DraftSendButton.tsx`:
  - While the window is open, adds a `Send template` / `Send free-form` toggle (`aria-pressed`) next to the existing `Approve & send` button; the existing template-name/language/params fields show when the toggle is on, and always show once the window has closed.
  - Template sends are flagged `preferTemplate: true` so the operator's explicit choice is honored.

## Tests
- Unit (`whatsappSender.test.ts`): template used while the window is open when `preferTemplate` is set; template name required when `preferTemplate` is set.
- UI-contract: `preferTemplate` wiring on the button, the `aria-pressed` toggle, and the `windowClosed || options.preferTemplate` server branch.
- `npm run check` green: 353 node tests + 4 issue-reports, lint/typecheck/build clean.
