Operators get a secret-free WhatsApp outbound health check so go-live troubleshooting doesn't require poking env vars.

## What changes
- `lib/outbound/whatsappSender.ts`: new `describeOutboundReadiness(config)` returning a breakdown for each requirement (enabled flag, access token present, phone number id present, graph version). Details are human explanations — never the credential values.
- New settings page `app/settings/outbound/page.tsx` (auth-gated, read-only): an overall "Ready to send / Not ready to send" status plus per-requirement OK / "Needs action" rows.
- Sidebar: "Outbound readiness" link under settings.

## Tests
- `describeOutboundReadiness` unit tests: per-key ready flags, explanations, and a guarantee that token/phone number id values never appear in any detail string.
- UI-contract assertions for the page's rendering, the secret-free framing, and the sidebar link.
- `npm run check` green: 335 node tests + 4 issue-reports, lint/typecheck/build clean.
