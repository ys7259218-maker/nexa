## Failed-sends page shows the exact failure total and its cap

The failed-sends list has been capped at 200 since #148, but the page only
showed the loaded rows — with older failures existing silently beyond the cap.
The opted-out and approvals pages already solve this with an exact head/count
total + a truncation flag; failed sends gets the same.

### Changes
- `lib/failedSends.ts`: `listFailedSends` now returns `{ sends, total, truncated }`.
  `total` comes from a parallel `count: "exact", head: true` query on outbound
  `failed` rows (the same filter as the list), so it is never subject to the
  returned-row cap. `truncated` is true when more failures exist than the newest
  200 shown.
- `app/failed-sends/page.tsx`: header now reads
  "N failed sends · M retryable of T total, showing the newest N" when trimmed,
  or "...· T total" otherwise.
- `lib/retryFailedSends.ts`: consumes `data.sends`; retry semantics and the
  server-side `RETRY_SCAN_LIMIT` are unchanged.
- Tests: `failedSends.test.ts` covers the exact total + truncation flag and the
  count-query smoke; both suites' mocks now model the head/count chain.
  `uiContracts.test.ts` pins the total/truncated shape and the count query.

Verified: lint 0 errors, typecheck clean, `npm test` 409 passing, production
build compiles, Playwright smoke 5/5, `npm audit` 0 vulnerabilities.

No migrations, no production changes — query/page/test-only.
