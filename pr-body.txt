## Inbox surfaces its exact counts and its 200/300 caps

Every other bounded list in the app (opted-out, approvals, failed sends) now
shows an exact total and an honest truncation note — but the main conversations
inbox was silently capping the sidebar at 200 chats and the selected thread at
300 messages with no indication that anything was hidden.

### Changes
- `lib/conversations.ts`: `getConversationInbox` now runs parallel
  `count: "exact", head: true` queries alongside the list and thread fetches and
  returns `{ totalConversations, listedConversations, conversationsTruncated,
  totalMessages, messagesTruncated }`.
  - The conversation count mirrors the active filter (all, or the `ilike`
    `customer_wa_id` search), so a search reports matching-chat totals.
  - `listedConversations` excludes a deep-linked conversation appended beyond
    the cap, so "showing the newest M" stays truthful.
- `app/conversations/page.tsx`: the "Recent chats" header now reads
  "N chats · showing the newest M" when capped (plain "N chats" otherwise);
  the selected thread header reports the exact message total and adds
  "showing the newest M" when the 300 cap bites.
- Tests: `conversations.test.ts` covers exact totals + truncation flags,
  including the deep-link "newest M" case with 500 chat fixtures; `FakeQuery`
  gained head/count support. `uiContracts.test.ts` pins the new fields, the
  count queries, and both page notes.

Verified: lint 0 errors, typecheck clean, `npm test` 411 passing, production
build compiles, Playwright smoke 5/5, `npm audit` 0 vulnerabilities.

No migrations, no production changes — query/page/test-only.
