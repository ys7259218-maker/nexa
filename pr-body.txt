Operators can now slice the outbound history by **send type**, so template campaigns are separately reviewable from free-form replies.

## What changes
- `lib/outboundHistory.ts`:
  - New `OutboundTemplateFilter = "all" | "freeform" | "template"` and `parseOutboundTemplateFilter(value)` (defaults to "all", never trusts raw strings).
  - `listOutboundHistory(client, statusFilter, templateFilter?, limit?)` now also filters `template_name` presence — `.not("template_name", "is", null)` for template sends and `.is("template_name", null)` for free-form. The existing call shape stays backward compatible.
- `app/outbound-history/page.tsx`:
  - Reads `?template=` alongside `?status=`, showing a second chip row (All sends / Free-form only / Template sends).
  - `buildHref(statusValue, templateValue)` XOR-combines both params so status and send-type filters stay composable and bookmarkable.

## Tests
- Unit (`outboundHistory.test.ts`): parser bounds; `.not`/`.is` filtering paths.
- UI-contract: param reading, chip row, `buildHref` combos, and the new helper shape.
- `npm run check` green: 354 node tests + 4 issue-reports, lint/typecheck/build clean.
