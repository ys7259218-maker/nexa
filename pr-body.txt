## Register previously-invisible unit suites and fix their broken mocks

While verifying the WhatsApp webhook safe-track, two suites existed that **never
ran under `npm test`** — and `lib/webhookLedger.test.ts` had **2 failing tests
hiding inside them**.

### What was wrong
`listWebhookEvents` chains `.order(...).limit(...)` on the Supabase filter
builder (which is synchronous), but the test's mock builder methods were
`async`, so each chained call returned a `Promise` instead of the mock — breaking
`query.order` / `query.order(...).limit` and failing the assertions.

### Changes
- `lib/webhookLedger.test.ts`: mock builder methods are sync chain-able now
  (matches real Supabase filter-builder behavior); `order` accepts the options
  arg the code passes.
- `package.json`: registered the four deterministic, env-free suites that were
  silently absent from `npm test` — `webhookLedger`, `inboundReadiness`,
  `issueReports`, `pendingApprovals`. `npm test` is now **433 tests** (was 411).
- `AGENTS.md`: the `next dev` auto-managed rule block (regenerated by the dev
  server; committing it keeps the working tree clean).

### Verified
- `npm test`: 433 pass, 0 fail (the 2 previously-failing cases now pass).
- Lint 0 errors, typecheck clean, production build compiles, Playwright smoke 5/5,
  `npm audit` 0 vulnerabilities.
- Live webhook GET verification on localhost with the real staging env: valid
  `hub.verify_token` -> `200` echoing the challenge; mismatched token -> `403`.
  No WhatsApp message was sent; no Meta secrets are involved or stored.
