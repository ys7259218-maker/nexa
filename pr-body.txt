# Failed-sends retry queue is opt-out aware

Query/page/test-only. **No migrations, no production changes.**

## Why

After #152, a customer who texts STOP is durably opted out and never receives a
draft or send — but the failed-sends work queue ignored opt-out state:
`listFailedSends` only read `customer_wa_id`, so an opted-out customer's failed
send still showed a "Retry" button and counted toward "Retry N retryable". The
send-time guard (`sendApprovedDraft`) already hard-blocks opted-out sends, so
nothing unsafe could actually send — but the operator work queue was misleading.
This slice makes the queue honest.

## What changed

- `lib/failedSends.ts`
  - Conversations query now selects `customer_opted_out_at`.
  - `FailedSend` gains `optedOut: boolean`.
  - `retryable = windowOpen && !template_name && !optedOut`, so opted-out sends
    are excluded from self-retry, Retry All, and the page's retryable count.
- `app/failed-sends/page.tsx` — opted-out rows show an "Opted out" chip and the
  note "This customer has opted out, so this send can't be retried." instead of a
  retry button (self-retry and Retry All both skip them).
- Tests — `lib/failedSends.test.ts` covers the opted-out case (window open but
  not retryable); ui-contract tests pin the field, the chip, the note, and the
  narrowed `retryable` expression.
- `NEXA_HANDOFF.md` refreshed to current state.
