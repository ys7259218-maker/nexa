# Delivery-funnel and dashboard exactness past 1,000 outbound messages + handoff refresh

Addresses both verified review items. **Query-only: no migrations, no production changes.**

## Why

Delivery-funnel and dashboard rates were computed from an unpaginated
`.select("status")` fetch of `messages`, which Supabase caps at 1,000 returned
rows. Above that volume the funnel silently understated attempted/delivered/read
counts and every rate derived from them.

## What changed

- `lib/deliveryFunnel.ts`
  - New `countOutboundDeliveryStages(client)`: four exact aggregate queries
    (`.select("status", { count: "exact", head: true })` filtered by
    `direction = outbound` and per-stage status). PostgREST computes these inside
    Postgres and returns no rows, so they are **not** subject to the 1,000-row
    cap; the "attempted" base is totals instead of shared-stage rows.
  - `combineDeliveryCounts` is the single source of truth for rate math, and
    `computeDeliveryFunnel` delegates to it.
  - `getDeliveryFunnel` now reads exact counts.
- `lib/dashboard.ts` — replaces the capped status fetch with
  `countOutboundDeliveryStages` and builds the funnel via `combineDeliveryCounts`,
  so `deliveredRatePercent`, `readRatePercent`, and `failedSendsCount` are exact.
- Tests
  - `lib/deliveryFunnel.test.ts` extended with exactness coverage past 1,000
    records and per-query contract checks (exact-head options, status filters,
    no limit/order).
  - New `lib/dashboard.test.ts` regression past 1,000 outbound messages.
  - Contract tests pinned to the exact-count mechanism.
  - **Fixed a test-suite-integrity gap: `lib/deliveryFunnel.test.ts` was never
    registered in the `npm test` file list** and had been silently skipped by
    the gate. It is now registered.
- `NEXA_HANDOFF.md` — refreshed to actual GitHub state (PR #35 and #150 merged,
  current `main` SHA, completed work, verification, real blockers, safest next
  action).
