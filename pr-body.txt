Operators can now search the conversations inbox by customer number prefix — the search box uses the same `?q=` param as the triage chips.

## What changes
- `lib/conversations.ts`:
  - `parseCustomerSearchValue(value)` — strips non-digits from the raw search-param, returning a pure-digit string or `null` (never trusts raw input).
  - `customerWaIdMatches(waId, query)` — tests whether the queried digit substring is present in the customer&apos;s masked number.
- `app/conversations/page.tsx`:
  - Reads `?q=` and applies `customerWaIdMatches` on each conversation before the triage filter.
  - Adds a `<form method="get" action="/conversations">` search box (`type="search"`, `name="q"`) with a hidden field for the active triage `filter`, so search and filter are composable/bookmarkable.
- `components/dashboard/Sidebar.tsx`: no change (search lives on the same conversations page).

## Tests
- Unit: `parseCustomerSearchValue` (digits, junk, absent input), `customerWaIdMatches` (true/false/null/empty).
- UI-contract: param reading, filter intersection, search-form attributes (`role="search"`, `type="search"`, `name="q"`, hidden-filter preservation), helper shape.
- `npm run check` green: 351 node tests + 4 issue-reports, lint/typecheck/build clean.
