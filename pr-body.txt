The audit log was hardwired to `message` events; operators can now filter the trail by entity type with validated query params.

## What changes
- `lib/auditEvents.ts`:
  - `AUDIT_ENTITY_TYPES` constant.
  - `parseAuditEntityFilter(value)` — validates unknown search-param values against the real entity types; returns `undefined` otherwise (never trusts raw query strings, so junk like `message; drop table` falls back to the default view).
  - `entityTypeLabel(type)` — human labels (AI employee / Workspace / Integration / Message).
- `app/settings/audit/page.tsx`:
  - Reads `?entity=` via the awaited `searchParams` promise and passes the validated filter to `listWorkspaceAuditEvents`.
  - Filter chips (All + each entity type) linking to `/settings/audit?entity=...`.
  - Generic row rendering across entity types (action label + entity chip + detail + timestamp), so the trail is no longer outbound-message-only.

## Tests
- `parseAuditEntityFilter` (valid + junk/absent values) and `entityTypeLabel` unit tests.
- UI-contract updates: filter wiring, chip rendering, and fallback label assertions.
- `npm run check` green: 338 node tests + 4 issue-reports, lint/typecheck/build clean.
