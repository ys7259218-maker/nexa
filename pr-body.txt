A centralized **pending approvals** work queue: every AI draft waiting on a human across all conversations, with inline approve-and-send.

## What changes
- `lib/pendingApprovals.ts`:
  - `listPendingApprovals(client, outboundReady, now)` — joins conversations, their `draft_blocked` outbound drafts (newest first), and each conversation's latest inbound timestamp into a single work queue.
  - Per-conversation window state reuses the same `isWithinServiceWindow` semantics as the inbox, so approve buttons behave identically here. `outboundReady` gates the window (no sends when outbound is disabled).
- `app/pending-approvals/page.tsx` — a row per draft: masked customer link into its conversation, window-open/closed chip, template tag, body preview, drafted time, and the existing `DraftSendButton` (free-form approve-and-send) when the window is open. Outbound-disabled banner, empty and error states included.
- `components/dashboard/Sidebar.tsx` — "Pending approvals" link directly under Conversations.

## Privacy / consistency
- Customer ids masked with `maskWhatsAppId`; all reads are RLS-scoped to the signed-in owner; the send path reuses the existing `/api/outbound/draft` route.

## Tests
- Unit: conversation/draft/inbound join, last-inbound selection, service-window gating (open/closed, outbound-disabled), DB-error mapping.
- UI-contract: page queue rendering, masked customer, button wiring, window chip, sidebar link, helper query shape.
