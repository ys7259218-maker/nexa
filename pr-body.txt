Outbound bubbles now reflect the full delivery lifecycle (Delivered / Read), with failed sends rendered distinctly in red instead of being lumped into the generic fallback.

## What changes
- `lib/conversations.ts`: new `outboundStatusLabel(status)` helper mapping `sent`/`delivered`/`read` to "Sent"/"Delivered"/"Read", and `failed` to "Failed to send".
- Inbox bubble: the success indicator (introduced in #122) now also handles outbound bubbles whose status is `delivered` or `read`, and shows `failed` in red with a distinct icon. Free-form/template label, masked provider id, and timestamp are shared across all these states.

## Tests
- `outboundStatusLabel` unit tests (all states + unknown passthrough).
- UI-contract assertions for the delivered/read/failed branches and `outboundStatusLabel` usage.
- `npm run check` green: 330 node tests + 4 issue-reports, lint/typecheck/build clean.
