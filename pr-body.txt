Operators can triage the conversation inbox instead of scanning an ever-growing flat list.

## What changes
- `lib/conversations.ts`:
  - `ConversationTriageFilter = "all" | "drafts" | "flagged"`.
  - `parseConversationTriageFilter(value)` — validates unknown search-param input, defaulting to `all` (never trusts raw query strings).
- `app/conversations/page.tsx`:
  - Reads `?filter=` and applies it client-side on the server render: **All chats** / **Draft pending** / **Safety flagged**.
  - Filter chips link back to `/conversations?filter=...` (or `/conversations` for All), so the view is shareable/bookmarkable.
  - Empty-filter message when the current filter matches nothing; the selected thread is unaffected.

## Tests
- `parseConversationTriageFilter` unit tests (known values, absent, and junk inputs).
- UI-contract assertions: param reading, the filtered list derivation (`drafts`/`flagged` branches), chip rendering, and filter link construction.
- `npm run check` green: 340 node tests + 4 issue-reports, lint/typecheck/build clean.
