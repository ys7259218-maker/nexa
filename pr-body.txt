## Summary

Wires Meta's 24-hour customer-service window into the outbound approve-and-send
workflow. Free-form drafts are only sent while the window is open (within 24h of
the customer's last inbound message); otherwise the send is refused — fail-closed,
no network call, nothing persisted.

## What changed

- `lib/server/draftSender.ts` — `sendApprovedDraft` now reads the conversation's most
  recent inbound message (`messages` where conversation + `direction = inbound`,
  newest first, limit 1) before sending:
  - last inbound read fails → `window_unverified` (nothing sent);
  - no inbound record, or older than 24h → `not_allowed` with a clear "customer-service window" message;
  - only an open window allows the free-form send through `isWithinServiceWindow`.
- Uses the existing pure policy layer `lib/outbound/sessionWindow.ts` (`SERVICE_WINDOW_MS`,
  `isWithinServiceWindow`) that was previously unwired.
- Tests: 3 new workflow cases (window closed with a stale inbound, no inbound record,
  window unverifiable) all asserting no send and no status write; the fake client
  in `whatsappSender.test.ts` now models `eq` ailters, `order`, and `limit` for the
  inbound lookup. UI-contract test extended to pin the window guard and its codes.
- Local `npm run check` green.

## Safety

Window enforcement happens before any sender call. Template messages (the only
legal outbound kind outside the window) remain explicitly deferred as documented
in `sessionWindow.ts`/`whatsappSender.ts`; this PR only makes the free-form path
legal-or-nothing.
