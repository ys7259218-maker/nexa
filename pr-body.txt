## What & why
Global search is now a real feature instead of a disabled placeholder. Enter a term from the workspace header (or the new `/search` page) and get grouped matches across the owner's stored records:

- **AI Employees** — name, business name, department
- **Conversations** — WhatsApp contact IDs (masked in results)
- **Messages** — full message bodies, linking back to the conversation thread
- **Call records** — customer names
- **Appointments** — customer, service, location

### Changes
- New `lib/search.ts`: parallel, RLS-scoped reads per table; LIKE values are sanitized so `%`, `_`, quotes, and backslashes can't widen or break the match; results grouped with per-group "view all" links.
- New `app/search/page.tsx` (server component, reads `?q=`) + matching `app/search/loading.tsx` shell.
- `DashboardHeader`: the long-disabled "Global search (coming later)" input is now an active `role="search"` GET form submitting to `/search`.
- `Navbar`: added a `Search` link (with `aria-current`), so search is reachable from every workspace page.

### Security & scope
- Every query runs with the signed-in user's cookie session; RLS keeps results scoped to the owner. No service-role key.
- Queries are capped at 100 chars and matched as plain substring containment — no full-text ranking, no indexes required.
