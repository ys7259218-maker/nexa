## Keep `issue_report` in the audit entity_type allow-list

Live-discovered during the staging migration push: the guarded issue-report
RPCs (`create_issue_report` v1, `delete_issue_report` v2) record audit rows
with `entity_type = 'issue_report'`, but the outbound-audit-trail migration
re-created the `audit_events` entity_type constraint without that value. The
constraint re-add then violated an existing real report row on nexa-staging-test
(`SQLSTATE 23514`), blocking `supabase db push`.

### Changes
- `supabase/migrations/20260905140000_outbound_audit_trail.sql` (and its
  `docs/migrations/` mirror): the recreated allow-list is
  `('ai_employee', 'workspace', 'integration', 'message', 'issue_report')`,
  matching the values both issue-report RPCs actually write.
- `lib/workspaceMigrations.test.ts` and `lib/uiContracts.test.ts`: pins updated
  to the five-value allow-list.

Verified: lint 0 errors, typecheck clean, `npm test` 411 passing, production
build compiles, Playwright smoke 5/5, `npm audit` 0 vulnerabilities.
