Template sends can now carry component params — required for any Meta template with placeholders (e.g. `order_confirmed {{1}} {{2}}`).

## What changes
- `sendApprovedDraft` accepts optional `templateParams: string[]` (bounded: ≤10 params, each ≤500 chars; malformed input fails fast with `invalid_template` instead of being silently dropped).
- Params are validated through `validateTemplate` and forwarded to `sendTemplateMessage`'s `componentParams`.
- `/api/outbound/draft` accepts and bounds `templateParams`.
- `DraftSendButton` template form gains a "Params (comma separated, max 10)" input; values are split/trimmed client-side and omitted when empty.

## Tests
- 3 new sender tests: params reach the transport, >10 params rejected with `invalid_template`, oversized param rejected before transport.
- Contract assertions for the route validation and UI copy.
- `npm run check` green: 325 node tests + 4 issue-reports, lint/typecheck/build clean.
